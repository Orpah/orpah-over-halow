3 · 边界与口径

  • 「被拒」只说明这一条没通过那道校验，不等于「防住了」—— 单条被拒不构成结论，任何一道防线都不能被写成“防住了攻击”。
  • 已知边界：路由器侧观测 xport 不在签名预像里 → 篡改它验签照样通过（清单里那条会显示“与期望一致：接受”）。而定位用的正是路由器侧测量 → 能冒充或控制一台路由器的人可以伪造定位；对策是多观测一致性判定（SPEC §8 原则 P-1、pos.js 的 consensus()）。
  • 攻击报文同样受 §5.8 限频约束，而限频在验签之前 → 注入太密时可能被挡在验签之前；那种条会显示「未等到结果」（可能死在限频/链路上），既不记成「被拒」也不记成「通过」。
  • 本页不含「已吊销设备」用例：页面用的是活密钥库，跑一次会把在跑的设备搞成验不过 → 它只在离线 demo_spoof.py / test_spoof.py 里覆盖（故上一栏「吊销表」显示 0 条）。
  • 清单、说明、防线名与「错误码 → 哪道防线」全部取自 spoof.py（CASES / DEFENSES / defense_of），页面不另写一份，脚本与页面不会漂移。
  • 口径：本页「攻击」指我们主动注入的测试报文（构造见 spoof.py）；真实链路上的异常一律只陈述「与预期不一致 / 与其余观测对不上」，不归因 —— 偏差成因不唯一（遮挡与多径、天线与接头、元件老化、标定漂移，也包括被改装或冒充）。
